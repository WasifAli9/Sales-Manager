# Sales Manager PWA — Replit Build Brief

App name: Closer

**Owner:** Nadeem
**Purpose in one line:** A PWA that forces me to spend 90% of my day selling, tells me exactly what to do on each platform for each product, and does not let me hide in "tweaking things."

Hand this whole file to the Replit Agent. Build in the milestone order in Section 9 — do not build everything at once.

---

## 1. What we're building

A single-operator sales command center. There are no customers yet and every product starts from zero, so the app's job is not reporting — it's **directing**. Every morning it hands me a ranked list of selling activities per product per platform, I tick them off, and at night it makes me account for the day.

**The operating rule the whole app enforces (the "90/10 rule"):**
- ~90% of my tracked day must be **SELL** or **CX** (customer experience).
- ~10% max on **BUILD / ADMIN** (product tweaks, website changes, tooling).
- The app actively flags and blocks drift into product/website tinkering, and pushes those tasks to a "delegate or defer" queue.

Every activity in the system carries one of four tags: **SELL**, **CX**, **BUILD**, **ADMIN**. The "Focus Guard" (Section 5.3) reads those tags in real time.

## 2. Tech stack & non-negotiables

| Layer | Choice |
|---|---|
| Framework | **Next.js (App Router) + React**, TypeScript |
| Styling | Tailwind CSS with CSS variables for the brand tokens in Section 3 |
| Database | **PostgreSQL** (Replit's Postgres). Use Prisma as the ORM |
| Auth | Single-user for v1 — a simple email+password login (NextAuth Credentials provider) so it's private on the web. No multi-tenant complexity |
| AI | Server-side calls to an LLM provider through a thin abstraction (Section 6). Support **both OpenAI and Anthropic** via one interface; pick per call with an env flag |
| PWA | **PWA-first** — installable, offline shell, works one-handed on mobile. See Section 7 |
| Hosting | Replit deployment |

Non-negotiables:
- **Mobile-first layout.** I run my day from my phone. Desktop is the secondary view.
- **Fast.** The daily list must load instantly from cache, then hydrate. Never make me wait to see today's tasks.
- **No dead ends.** Every screen ends with a next action.

## 5. Core modules

### 5.1 Products & Goals
- CRUD for products. Each product holds its own goals, platform states, AI analyses, and activities.
- Per product I set: **revenue target**, **activity targets**, and a **30-day goal**.
- Seed with my real portfolio on first run (Section 10) so it's usable immediately.

### 5.2 AI Marketing Strategist (per product) — the brain
For each product, an on-demand "strategist" run produces and caches (`AiAnalysis`):
1. **ICP profile** — the single most specific "bleeding-neck" persona: who they are, the exact pain, why they'd buy now without education, and where they congregate (specific communities/platforms, not "LinkedIn" but which groups/subreddits/associations).
2. **Competitor landscape** — who already solves this, their weaknesses/gaps, and therefore the wedge value I can deliver. *(Grounding note in Section 6 — this must not be hallucinated.)*
3. **Value proposition** — the one sentence that makes that persona feel understood instantly.
4. **Go-to-market plan** — realistic path to reach them using only the channels I already run, zero paid ads.
5. **Cadence plan** — when to run a webinar, what/when/how often to post per platform, and the outreach angle.

The strategist then **generates the daily activity list** (5.3) from the GTM + cadence + current platform stage, respecting the 90/10 rule.

**Copy/voice rules baked into every strategist prompt:** output must read human — direct, specific, no AI tells, no filler adjectives, no "in today's fast-paced world." When it drafts outreach or offers, use direct-response construction (clear promise, proof, specific mechanism, risk reversal, deadline). Offers should be built as a genuine no-brainer for the *first* customers, not generic.

### 5.3 Daily Command Center + Focus Guard (the home screen)
- Top: **today's date, the day's one-line push from the Coach** (5.7), and a **Focus Guard meter** showing the live SELL+CX vs BUILD+ADMIN split against the 90/10 target.
- Below: **ranked activity list**, grouped by platform, each tagged SELL/CX/BUILD/ADMIN, with effort minutes. I tick them off.
- **Focus Guard behaviors:**
  - If BUILD/ADMIN creeps over 10% of planned or logged time, the meter turns amber and it prompts: *"This is a tweak, not a sale. Delegate, defer, or delete it."* with one-tap **Delegate** (moves to a delegate queue) / **Defer**.
  - Adding a BUILD/ADMIN activity always asks "who can own this instead of you?" before it's allowed onto today.
- **Prioritized by platform:** the list orders platforms by where the highest-leverage next selling action is, based on each platform's readiness stage (5.4).

### 5.4 Platform Readiness Tracker
- For each product × platform, track the **stage**: not_started → setup → warming → active → scaling.
- The app **determines where I am** by asking a short setup questionnaire per platform the first time (Do you have a profile? Content live? Outreach running? Booking link?) and by watching `last_activity_at`.
- Stage drives the strategist's daily tasks: a `not_started` LinkedIn gets "optimize profile + connect with 20 ICP"; an `active` one gets "post + 15 DMs + book 2 calls."

### 5.5 Resource & Automation Stack + Tool Advisor
- Register my stack: **Apollo.io** (enrichment/lists), **Canva** (posts), **HeyGen** (video), **GoHighLevel** (scheduling/CRM), **Claude + ChatGPT** (AI), webinars.
- Each resource records what it automates and its cost, and gets **its own goals + progress** (e.g. Apollo: 500 enriched ICP contacts/month; LinkedIn: 20 posts/month).
- **Tool Advisor:** an AI action that, given my current manual tasks and stack, suggests **new tools/automations so I stop relying on people** — e.g. chaining Apollo → GHL, auto-drafting LinkedIn posts via the LLM, HeyGen batch video, n8n/Make for the glue, auto-scheduling. Suggestions land in `Resource` as `status=considering` with a one-line "what it removes from your plate."

### 5.6 Goals, Targets & Progress
- Global + per-product + per-platform + per-resource goals, each with target, current, unit, deadline, and a progress bar.
- **30-day goals** get their own board with days-remaining and required daily pace ("you need X/day to hit this — today you did Y").
- A single **"Number"** view: total pipeline/ARR target vs current across all products, always one tap away.

### 5.7 The Coach (motivation engine)
Direct, no-BS accountability. It surfaces a push on the home screen each morning and a verdict each night. Themes I want it to hit: *the magic is on the other side of discomfort; go big or go home; protect and be selfish with your selling hours; if you don't move now the numbers don't happen.*

**Design note (important, and I'd build it this way on purpose):** aim the tough love at **the behavior and the plan**, never at my identity. "You spent two hours on the website and booked zero calls — that's the gap, fix it tomorrow" lands and changes behavior. "You're a failure / you'll look like an idiot" reads hard but measurably *reduces* follow-through and burns out over weeks — it trains avoidance of the app, which is the opposite of the goal. So: sharp on the miss, specific on the fix, relentless on the next action. Tie every push to my own stated stakes and today's concrete task. That keeps it brutal *and* effective.

Coach inputs: today's Focus Guard split, activities done vs planned, pace against 30-day goals, last reflection.

### 5.8 Daily Reflection
- End-of-day form: what went well, what went wrong, what to improve, energy (1–5).
- On submit, the LLM returns a **tough-love review**: names the biggest leak, one thing to cut, one thing to double down on tomorrow, and it auto-adjusts tomorrow's first three activities. Stored on the `Reflection` row and fed back to the Coach.

### 5.9 Vision Board
- Visual board of the north star (**global, millions in ARR**) plus milestones and a **charity giving target** as a first-class goal (`kind=charity`) with its own progress bar tied to revenue.
- Support image tiles (upload/URL), milestone tiles, and the charity tile. This is the screen I open when I need the "why."

## 6. AI integration architecture

- All LLM calls run **server-side** (Next.js route handlers / server actions). Never expose keys to the client.
- One provider abstraction: `getStrategist(provider)` returning a common `run(kind, product, context)` — swap OpenAI/Anthropic via `AI_PROVIDER` env.
- **Cache aggressively.** ICP/competitor/value-prop/GTM change rarely — store in `AiAnalysis` and only re-run on demand or when I edit the product. Daily activities regenerate each morning from cached analysis + live platform stages, so the expensive research isn't re-billed daily.
- **Grounding for competitor research (do not skip):** raw LLM competitor "facts" hallucinate. Use a provider **web-search tool** (OpenAI web search or Anthropic web search) for the competitor step, or let me paste in research and have the model structure it. Mark ungrounded output clearly in the UI so I never act on invented competitors.
- **Structured output:** prompt the model to return strict JSON only (no prose, no markdown fences), parse safely, store as `jsonb`. Each `kind` has a fixed schema so the UI can render it.

Strategist prompt skeleton (per product):
```
You are a direct-response B2B growth strategist for a solo founder with
NO customers yet and zero ad budget. Channels available: LinkedIn, Apollo
(enrichment+lists), email, webinars, YouTube, X, Canva, HeyGen, GoHighLevel.
Product: {name} — {description} — target market {target_market}.
Current platform stages: {platformStates}.
Return JSON matching the {kind} schema. Rules: name the single most specific
bleeding-neck persona; be concrete about where they congregate; ground
competitor claims in the provided search results only; write all customer-
facing copy human and specific (no AI tells, no filler); construct any offer
as a genuine no-brainer for first customers with clear risk reversal.
Enforce the 90/10 rule: at least 90% of generated activities must be
SELL or CX.
```

## 7. PWA requirements

- `manifest.json`: name "Sales Manager", short_name, `display: standalone`, theme_color `#0B1220`, background_color `#0B1220`, maskable icons (192/512), start_url `/`.
- **Service worker** (next-pwa or a custom one): cache the app shell + today's activities for **offline read**; queue tick-offs made offline and sync on reconnect (background sync or a simple retry queue).
- **Installable** on iOS/Android; add an in-app "Install" nudge.
- Home screen must render from cache in <1s, then hydrate live data.
- One-handed mobile ergonomics: bottom tab bar, thumb-reachable primary actions.

## 9. Build order (milestones — build in this sequence)

1. **M1 — Skeleton:** Next.js + Tailwind + Prisma + Postgres, brand tokens, auth, bottom-tab shell, PWA manifest + basic service worker. Seed data loads.
2. **M2 — Products, Goals, Platform states:** full CRUD, progress bars, the "Number" view.
3. **M3 — Daily Command Center + Focus Guard:** manual activities, tagging, 90/10 meter, delegate/defer queue.
4. **M4 — AI Strategist:** provider abstraction, ICP/competitor(grounded)/value-prop/GTM/cadence, caching, JSON rendering.
5. **M5 — AI daily activity generation** from strategist + platform stages, feeding M3.
6. **M6 — Coach + Reflection:** morning push, night verdict, reflection form + LLM review adjusting tomorrow.
7. **M7 — Resource stack + Tool Advisor.**
8. **M8 — Vision Board** (incl. charity goal) + offline sync polish.

Each milestone should be independently runnable.
